# Cloud Deployment Guide

This guide deploys C3 LegalDoc Navigator without Docker using managed services:

| Layer | Service |
|---|---|
| Frontend | Vercel |
| Backend API | Render Web Service |
| Relational database | Neon PostgreSQL |
| Vector search | Qdrant Cloud |
| File storage | S3-compatible object storage (AWS S3 or Cloudflare R2) |
| Secrets | Platform environment variables |

## Prerequisites

- GitHub repository connected to Render and Vercel
- [Neon](https://neon.tech) account
- [Qdrant Cloud](https://cloud.qdrant.io) account
- S3-compatible storage (AWS S3 or Cloudflare R2)
- Render and Vercel accounts
- OpenAI API key (embeddings + chat)
- Anthropic, Groq, and/or Google API keys as configured in provider routing
- Python 3.12 and Node.js 20 for local verification

## Architecture

```
Vercel (React)
    │
    ▼
Render (FastAPI)
    ├── Neon PostgreSQL     → documents, users, chat, metadata
    ├── Qdrant Cloud        → document chunk vectors
    └── S3 / R2             → uploaded PDF/DOCX/TXT files
```

## Deployment Order

1. Create Neon project and run `scripts/neon_bootstrap.sql`
2. Create Qdrant Cloud cluster
3. Create S3 bucket (or R2 bucket)
4. Deploy Render backend with environment variables
5. Verify `GET /health`
6. Deploy Vercel frontend with `VITE_API_BASE_URL`
7. Update Render `CORS_ORIGINS` with Vercel URL
8. Run end-to-end tests

---

## 1. Neon PostgreSQL Setup

1. Create a project at [neon.tech](https://neon.tech).
2. In the Neon SQL Editor, run:

```sql
-- scripts/neon_bootstrap.sql
CREATE EXTENSION IF NOT EXISTS vector;
```

3. Copy two connection strings from **Dashboard → Connection Details**:

| Variable | Neon connection type | Used for |
|---|---|---|
| `DATABASE_URL` | **Pooled** connection | Async runtime (`asyncpg`) |
| `DATABASE_SYNC_URL` | **Direct** connection | Alembic migrations (`psycopg2`) |

Example format:

```env
DATABASE_URL=postgresql://user:pass@ep-xxx-pooler.region.aws.neon.tech/neondb?sslmode=require
DATABASE_SYNC_URL=postgresql://user:pass@ep-xxx.region.aws.neon.tech/neondb?sslmode=require
```

The app normalizes `postgresql://` URLs to the correct SQLAlchemy drivers and maps SSL query parameters automatically.

4. Render runs `alembic upgrade head` on startup to create all relational tables.

> **Note:** Document vectors are stored in Qdrant, not in Neon. Neon still holds chunk metadata (`document_embeddings` table) and all other app data.

---

## 2. Qdrant Cloud Setup

1. Create a cluster at [cloud.qdrant.io](https://cloud.qdrant.io).
2. Copy:
   - **Cluster URL** → `QDRANT_URL` (e.g. `https://abc123.region.aws.cloud.qdrant.io:6333`)
   - **API Key** → `QDRANT_API_KEY`
3. Set on Render:

```env
VECTOR_BACKEND=qdrant
VECTOR_DIMENSION=1536
QDRANT_URL=https://your-cluster.region.aws.cloud.qdrant.io:6333
QDRANT_API_KEY=your-qdrant-api-key
QDRANT_COLLECTION_NAME=document_embeddings
```

The API creates the collection automatically on first startup if it does not exist.

## 3. S3-Compatible Storage Setup

Works with **AWS S3** or **Cloudflare R2**.

### AWS S3

1. Create a private bucket (e.g. `legal-documents`).
2. Create an IAM user with `s3:PutObject` permission.
3. Set on Render:

```env
STORAGE_BACKEND=s3
S3_BUCKET=legal-documents
S3_ACCESS_KEY_ID=AKIA...
S3_SECRET_ACCESS_KEY=...
S3_REGION=us-east-1
S3_PATH_PREFIX=uploads
# Leave S3_ENDPOINT_URL empty for AWS
```

### Cloudflare R2

1. Create an R2 bucket.
2. Create R2 API tokens.
3. Set on Render:

```env
STORAGE_BACKEND=s3
S3_BUCKET=legal-documents
S3_ACCESS_KEY_ID=...
S3_SECRET_ACCESS_KEY=...
S3_REGION=auto
S3_ENDPOINT_URL=https://<account-id>.r2.cloudflarestorage.com
S3_PATH_PREFIX=uploads
```

## 4. Render Backend Deployment

Use `render.yaml` as the Blueprint, or configure manually:

| Setting | Value |
|---|---|
| Runtime | Python 3.12 |
| Build Command | `pip install --upgrade pip && pip install -r requirements.txt` |
| Start Command | `alembic upgrade head && uvicorn app.main:app --host 0.0.0.0 --port $PORT` |
| Health Check | `/health` |

`apt.txt` installs `tesseract-ocr` for scanned PDF support.

### Required Render environment variables

```env
APP_ENV=production
APP_DEBUG=false
SECRET_KEY=<auto-generated or random 32+ chars>
CORS_ORIGINS=["https://your-app.vercel.app"]

# Neon
DATABASE_URL=postgresql://...@ep-xxx-pooler...neon.tech/neondb?sslmode=require
DATABASE_SYNC_URL=postgresql://...@ep-xxx...neon.tech/neondb?sslmode=require

# Qdrant
VECTOR_BACKEND=qdrant
QDRANT_URL=https://your-cluster.region.aws.cloud.qdrant.io:6333
QDRANT_API_KEY=...
QDRANT_COLLECTION_NAME=document_embeddings

# Storage
STORAGE_BACKEND=s3
S3_BUCKET=legal-documents
S3_ACCESS_KEY_ID=...
S3_SECRET_ACCESS_KEY=...
S3_REGION=auto
S3_ENDPOINT_URL=          # only for R2
S3_PATH_PREFIX=uploads

# LLM providers
OPENAI_API_KEY=...
OPENAI_EMBEDDING_MODEL=text-embedding-3-small
OPENAI_CHAT_MODEL=gpt-4o-mini
ANTHROPIC_API_KEY=...
ANTHROPIC_CHAT_MODEL=claude-3-5-sonnet-20241022
GEMINI_API_KEY=...
GEMINI_CHAT_MODEL=gemini-2.5-flash
GEMINI_EMBEDDING_MODEL=gemini-embedding-001
GROQ_API_KEY=...
GROQ_CHAT_MODEL=llama-3.3-70b-versatile
EMBEDDING_PROVIDER=openai
DEFAULT_LLM_PROVIDER=openai
FALLBACK_LLM_PROVIDER=anthropic
```

Variables with defaults in `config.py` (like `CHUNK_SIZE`, `TOP_K_RETRIEVAL`) do not need to be set unless you want to override them.

## 5. Vercel Frontend Deployment

| Setting | Value |
|---|---|
| Root Directory | `frontend` |
| Framework | Vite |
| Build Command | `npm run build` |
| Output Directory | `dist` |

```env
VITE_API_BASE_URL=https://your-render-service.onrender.com
```

No trailing slash. Redeploy Vercel after changing this variable.

## 6. Security

- HTTPS only for all service URLs
- Keep `QDRANT_API_KEY`, `S3_SECRET_ACCESS_KEY`, and LLM keys on Render only — never on Vercel
- Set `APP_DEBUG=false` in production
- Set `CORS_ORIGINS` to the exact Vercel URL
- Keep S3/R2 buckets private
- Upload validation: only `pdf`, `docx`, `txt` up to `MAX_UPLOAD_SIZE_MB`

## 8. Troubleshooting

**Database connection fails**
- Use pooled URL for `DATABASE_URL`, direct URL for `DATABASE_SYNC_URL`
- Ensure `sslmode=require` is in the connection string
- URL-encode special characters in the password

**`type "vector" does not exist`**
- Run `scripts/neon_bootstrap.sql` in Neon SQL Editor

**Qdrant connection fails**
- Confirm `QDRANT_URL` includes `https://` and port `:6333`
- Confirm `VECTOR_BACKEND=qdrant`
- Check Qdrant Cloud cluster is running

**Upload fails**
- Confirm `STORAGE_BACKEND=s3`
- Confirm bucket name and credentials
- For R2, confirm `S3_ENDPOINT_URL` is set
- Check file size and extension limits

**Frontend CORS errors**
- Add exact Vercel URL to `CORS_ORIGINS` on Render
- Redeploy backend after CORS change

**Slow first response**
- Render Starter plan cold starts take 30–60 seconds
